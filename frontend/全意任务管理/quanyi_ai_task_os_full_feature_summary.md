# 全意 AI Task OS｜完整功能总览 V1.0

## 1. 产品定位

全意 AI Task OS 是一套面向全意内部小团队的 AI 原生任务协作系统。

它的核心不是单纯管理待办事项，而是把聊天、会议、项目、任务、AI Agent、外部联系人、求助和知识沉淀连接进同一套工作流，让：

- 人与人协作
- 人与 AI 协作
- AI 与 AI 协作

都能围绕统一任务对象展开。

产品目标是减少任务遗漏、降低负责人分配和追问成本、提升 AI 参与工作的透明度，并让项目推进过程可记录、可提醒、可验收、可沉淀。

## 2. 核心角色

### 2.1 CEO / 项目负责人

主要能力：

- 创建项目
- 创建和分配任务
- 审核候选任务
- 确认会议任务
- 查看项目整体进度
- 查看风险和阻塞
- 验收任务
- 调整负责人、优先级和截止时间
- 查看团队贡献

### 2.2 普通成员

主要能力：

- 查看个人任务
- 接收和确认任务
- 执行任务
- 更新任务状态
- 提交结果
- 发起求助
- 回答他人求助
- 认领开放任务
- 使用 AI Agent 辅助执行
- 查看个人贡献

### 2.3 AI Agent

主要能力：

- 识别聊天和会议中的潜在任务
- 生成候选任务
- 补全任务字段
- 提供执行建议
- 执行任务
- 更新执行状态
- 输出执行结果
- 检索历史知识
- 生成会议摘要
- 提醒风险和逾期事项
- 通过 CLI / API 操作任务

### 2.4 外部联系人

外部联系人不直接登录系统。

系统用于记录：

- 姓名
- 公司
- 职位或角色
- 关联项目
- 当前待办
- 预计回复时间
- 内部对接人
- 最近跟进记录

6. 哪些项目存在风险

- 今日可执行任务数

- 已阻塞任务数量

### 4.2 今日可执行

- 任务验收
- 时间调整申请

## 6. 任务管理

### 6.1 任务基础字段

每个任务至少包含：

- 任务标题
- 所属项目
- 所属阶段
- 背景
- 目标
- 交付物
- 验收标准
- 发起人
- 负责人
- 执行人
- 协作者
- 执行模式
- 当前状态
- 优先级
- 截止时间
- 任务来源
- 前置任务
- 后续任务
- 阻塞原因
- 外部依赖
- 任务积分

### 6.2 任务执行模式

任务支持三种执行模式：

#### 人工执行

主要由成员完成。

#### AI 执行

主要由 Agent 或 Codex 完成，人工负责确认和验收。

#### 人机协作

AI 负责：

- 搜集资料
- 生成草稿
- 分析
- 写代码
- 输出建议

人负责：

- 判断
- 修改
- 补充
- 验收
- 对外沟通

### 6.3 任务状态

业务状态包括：

- 候选任务
- 待负责人确认
- 待开始
- 进行中
- 等待外部
- 已阻塞
- 待人工确认
- 待验收
- 已完成
- 已取消

### 6.4 AI 执行子状态

AI 执行状态包括：

- 排队中
- 执行中
- 需要信息
- 执行失败
- 执行完成
- 已取消

AI 执行完成不等于业务完成。

标准流程：

```text
AI 执行完成
→ 人工确认
→ 业务验收
→ 任务完成
```

任务详情页展示：

- 截止时间

#### 主内容

- 背景
- 目标
- 交付物
- 验收标准
- AI 建议
- 子任务
- 执行结果
- 附件

#### 属性区

- 优先级
- 阶段
- 执行者
- Agent
- 审核人
- 前置任务
- 后续任务
- 外部联系人

#### 协作区

- 评论
- 求助
- 决策记录
- 执行日志
- 状态变化记录

### 6.6 子任务

支持：

## 7. 候选任务自动拾取

### 7.1 候选任务来源

系统可以从以下来源识别潜在任务：

- 聊天
- 会议
- 文档
- 浏览器上下文
- Codex
- CLI
- 手动输入

### 7.2 自动拾取流程

```text
工作上下文产生信息
→ AI 判断是否存在任务
→ 生成候选任务
→ 人工确认
→ 创建正式任务
```

### 7.3 候选任务内容

候选任务包含：

- 原始来源
- 原始上下文
- AI 提取标题
- AI 提取背景
- 推荐项目
- 推荐阶段
- 推荐负责人
- 推荐执行模式
- 推荐截止时间
- 置信度
- 缺失字段

### 7.4 候选任务操作

支持：

- 确认创建
- 修改后创建
- 关联已有任务
- 暂存为想法
- 忽略

### 7.5 候选任务确认原则

V1：

- AI 自动拾取
- 人工确认创建

后续演进：

1. 全部人工确认
2. 明确规则场景自动创建
3. 高置信度任务自动创建
4. 全程支持撤销、审计和反馈

## 8. 会议能力

### 8.1 会议记录

支持记录：

- 会议名称
- 参与人
- 时间
- 原始内容
- 会议摘要
- 决策事项
- 候选任务

### 8.2 全局会议摘要

AI 自动生成：

- 会议背景
- 核心讨论
- 已确认决策
- 待确认问题
- 风险
- 候选任务

### 8.3 个性化会议摘要

针对每位成员生成：

- 与本人相关的信息
- 本人任务
- 本人需要确认的事项
- 本人后续行动

### 8.4 会议任务确认

标准流程：

```text
会议结束
→ AI 生成纪要
→ AI 提取候选任务
→ 会议负责人统一审核
→ 正式下发
→ 员工确认接收
```

员工可以反馈：

- 信息不足
- 时间冲突
- 任务识别错误
- 负责人错误

## 11. 当前可执行与等待外部

### 11.1 当前可执行

包括：

- 待开始
- 进行中
- 内部可解决的阻塞
- 待人工确认
- 待验收

### 11.2 等待外部

当任务依赖客户、合作方或供应商时，可转入等待外部。

必须记录：

- 等待对象
- 所属公司
- 等待事项
- 预计回复时间
- 内部跟进人
- 最近跟进时间

### 11.3 等待外部提醒

系统在以下情况提醒：

- 距预计回复时间 24 小时
- 已超过预计回复时间
- 对方已回复
- 长时间未跟进

### 11.4 外部反馈后的处理

收到外部反馈后可以：

- 恢复原任务
- 创建后续内部任务
- 转 AI 执行
- 继续等待
- 完成事项

## 15. 游戏化与贡献记录

### 15.1 贡献行为

系统记录：

- 完成指派任务
- 完成开放任务
- 解决求助
- 沉淀知识
- 创建可复用 Agent
- 创建可复用工作流

### 15.2 任务积分

建议：

- 小任务：5 分
- 普通任务：10 分
- 复杂任务：20 分
- 关键任务：30 分

额外积分：

- 开放任务认领：+5
- 解决求助：+5
- 知识沉淀：+3
- 加急任务：由创建者设置

### 15.3 贡献页面

展示：

- 本周积分
- 完成任务数
- 认领任务数
- 解决求助数
- 知识沉淀数
- 徽章
- 项目贡献

不展示：

- 强制公开排名
- 与薪酬直接绑定
- 复杂竞争机制

### 20.2 重复任务

- 关联已有任务
- 合并任务
- 继续创建

### 20.3 任务信息不完整

允许创建，但标记：

- 缺少背景
- 缺少验收标准
- 缺少截止时间
- 缺少负责人

### 20.4 重要操作

以下操作需要确认或支持撤销：

- 删除任务
- 取消任务
- 改变负责人
- 转等待外部
- 通过验收
- 修改积分

## 22. V1 核心流程

### 22.1 聊天转任务

```text
聊天信息
→ AI 识别
→ 候选任务
→ 人工确认
→ 正式任务
```

```text
会议结束
→ AI 纪要
→ 候选任务
→ 负责人确认
→ 员工确认
→ 正式执行
```

```text
待开始
→ 进行中
→ 提交结果
→ 待验收
→ 已完成
```

```text

```

```text

→ 收到反馈

```

```text
发布问题
→ AI 初步回答
→ 推荐专家
→ 人工回答
→ 确认解决
→ 知识沉淀
```
