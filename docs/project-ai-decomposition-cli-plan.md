# 项目 AI 拆解、集中分配与薄 CLI 实施方案

## 目标

在不改变现有任务状态机的前提下，为单个大项目提供一条完整路径：

1. 人工在项目内发起 AI 拆解。
2. AI 根据项目目标、里程碑、阶段、现有任务和项目成员生成候选小任务。
3. 候选集中展示，人工逐项打开并修改标题、背景、交付物、负责人、验收人和截止时间。
4. 人工确认后才创建正式任务，并明确选择由人执行、AI 执行或人机协同。
5. 项目内持续展示候选、待接收、执行中、待确认、待验收、完成和阻塞情况，以及成员负荷和整体进度。
6. 提供只调用同一后端 API 的薄 CLI，供 Codex、脚本和自动化工具使用。

## 唯一真实数据源

- PostgreSQL 是唯一持久化数据源。
- FastAPI 是唯一写入边界；网页和 CLI 均不得直接连接数据库。
- AI 拆解结果继续写入现有 `SourceSnapshot` 和 `CandidateTask`，不新增另一套“AI 小任务”表。
- 正式任务继续使用现有 `Task`、状态机、版本号、幂等键、审计事件和人工验收闭环。
- 项目进度继续由阶段和正式任务在服务端聚合，前端与 CLI 只读取结果。

## 实现路径

### P0：项目级 AI 拆解 API

- 新增项目拆解请求接口，输入为人工补充要求与期望候选数量。
- 服务端自动拼装项目目标、里程碑、阶段、现有任务及可分配成员上下文。
- Model Gateway 使用独立 Prompt 版本输出候选任务，不直接创建正式任务。
- 每次拆解保留不可变来源快照、AI 模式、降级原因、调用日志和审计信息。
- 只有项目成员可以发起拆解；全局可见但未加入项目的账号不可发起。

### P0：项目集中审核和分配页面

- 在项目空间增加“任务总览”入口。
- 顶部展示服务端项目进度和各状态真实数量。
- 中部展示项目成员卡片、每人任务数量、进行中数量和逾期/阻塞数量。
- 下部集中展示 AI 候选与正式任务。
- 点击候选进入现有审核弹窗，可修改字段并确认创建。
- 执行方式可选择 `HUMAN`、`AI` 或 `HYBRID`；AI 不得绕过负责人确认和验收。

### P1：薄 CLI

- CLI 通过 `AI_TASK_BASE_URL` 和 `AI_TASK_TOKEN` 调用同一 API。
- 默认输出人类可读 JSON，支持 `--json` 供 Codex 和脚本稳定解析。
- 首批命令覆盖：登录、项目列表/状态、项目拆解、候选列表/修改/确认、项目任务列表。
- CLI 不包含 SQL、模型密钥或服务器密钥，也不复制领域状态机。
- 写命令由服务端继续执行权限、版本和幂等校验。

## 底线

1. AI 只能生成候选，不能直接创建或完成正式任务。
2. 候选必须由有权限的人确认；分给其他人的任务仍需对方接收。
3. AI 执行结果仍进入人工确认与人工验收，不得自动记为完成。
4. 全局可见不等于可拆解、可分配或可确认。
5. 不允许前端或 CLI 自算并回写项目进度。
6. 不允许 CLI 直接访问 PostgreSQL、读取服务端 `.env` 或持有模型供应商密钥。
7. Live、Mock、Fallback 必须继续明确标识；降级结果不能伪装为真实 AI。
8. 所有写操作必须保留审计、版本冲突和幂等保护。

## 验收标准

- 项目成员可从项目页面发起拆解，并得到持久化候选；非项目成员收到 403。
- 刷新页面后候选、任务分配和项目进度不丢失。
- 候选可指定负责人、验收人、截止时间及执行方式，确认后只生成一个正式任务。
- 项目任务总览中的数量、成员负荷和进度均来自真实 API 数据。
- CLI 与网页读取到相同项目、候选和任务；CLI 写入后网页刷新可见。
- 后端测试、前端类型检查、真实性检查、生产构建和 CLI 测试全部通过。
