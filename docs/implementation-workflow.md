# 降低执行错误的实施工作流

## 每个纵向切片

1. 先更新领域契约和 ADR。
2. 添加数据库迁移及回滚说明。
3. 实现领域服务、事务、幂等和权限守卫。
4. 暴露 API，并由 OpenAPI 生成前端类型/client。
5. 通过 `useHub` 兼容层接入页面，逐域替换本地状态。
6. 补齐 loading、empty、forbidden、conflict、error 和 retry 状态。
7. 运行单元、API 集成、前端类型检查和关键 E2E。
8. 按验收场景人工走查，保存结果后再提交和推送。

## 禁止事项

- 不在路由中直接修改任务状态。
- 不为关键状态操作做前端乐观成功。
- 不同时手写后端和前端两套 API 枚举。
- 不覆盖历史提交、模型输出或审计记录。
- 不在没有幂等键或唯一约束时发贡献、确认候选或启动 AI。
- 不将 Mock/Fallback 标记为真实模型结果。

## 每阶段完成定义

- 迁移可从空库运行，也可从上一阶段升级。
- API、权限、审计、UI 和自动测试同时完成。
- 有明确失败状态、重试策略和回滚方式。
- 构建通过且核心验收场景通过。
- 独立 Git 提交并推送后才进入下一阶段。
