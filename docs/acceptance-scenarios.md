# MVP 验收场景

## 阶段 1：只读贯通

- 登录后由服务端返回当前用户和权限。
- 前端从 API 展示至少一个真实数据库项目及任务。
- 刷新和更换浏览器后业务数据不丢失。
- 未登录请求被拒绝，非项目成员不能读取项目。

## 阶段 2：人工任务闭环

- 创建、分配、接收、开始、提交、退回、重提和通过完整走通。
- 空提交被拒绝；非验收人不能完成任务。
- 每次提交保留版本；每次状态变化有历史和审计。
- 重复点击候选确认、提交或验收不会产生重复数据和贡献。

## 阶段 3：等待外部

- 缺少等待对象、事项、内部跟进人、预计时间或恢复动作时不能进入等待外部。
- 正常等待不报警；临期进入提醒；逾期升级。
- 收到反馈后恢复进行中，未发送提醒被取消。

## 阶段 4：候选提取

- 粘贴来源原文后保存不可变快照并得到结构化候选。
- 不合格模型输出不能写入候选表。
- 候选可修改、暂存、忽略、创建或关联，且保留证据。
- 分配他人后必须由负责人二次接收。

## 阶段 5：AI 执行

- AgentRun 按 QUEUED/RUNNING/SUCCEEDED 或失败状态流转。
- 真实模型调用记录模型、Prompt 版本、耗时、Token、成本和结果。
- AI 输出必须经负责人确认后才能提交验收。
- Live 失败后的 Fallback 有醒目标识，不能计为 Live 验收成功。
- 服务重启后遗留 RUNNING 能恢复、重试或明确失败关闭。
